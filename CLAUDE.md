# CLAUDE.md

Контекст для Claude Code при будущих правках этого проекта.

## Что это

Лонгрид-страница про советских композиторов кино (Исаак Шварц, Владимир Дашкевич), собранная как **React + Vite + Electron** приложение. Дизайн взят из Figma (`https://www.figma.com/design/9F1ucAVFjtYshSmFnnV5N9/`) и рендерится **1:1**: каждая глава = один большой SVG-снимок страницы из Figma, поверх которого в нужных местах по координатам наложены интерактивные React-компоненты (слайдеры, видео, аудио-кассеты).

## Стек

- **React 18** + **Vite 5** (dev на `http://localhost:5173`)
- **Electron 31** для desktop-сборки
- **electron-builder** для упаковки (Windows / macOS / Linux)
- Без TypeScript, без Redux, без UI-фреймворков. Чистый JSX + один `styles.css`.

## Команды

```bash
npm run dev               # Vite dev server :5173
npm run build             # production bundle → dist/
npm run preview           # preview dist локально
npm run electron:dev      # Vite + Electron в dev
npm run electron:start    # Electron на готовом dist (требует npm run build сначала)
npm run electron:build    # упаковка через electron-builder → release/
```

В Linux/WSL Electron запускается с флагом `--no-sandbox` (он уже зашит в скриптах) — без него падает с FATAL под root.

## Архитектура данных

Все интерактивные элементы описаны декларативно в `src/data/chapters.js`. Каждая глава — объект:

```js
{
  id: 'chN',
  title: '...',
  src: '/assets/chapter-N-...svg',
  width: 1920,         // всегда 1920
  height: CHN_H,       // высота КРОПНУТОГО SVG
  arrows: [...],       // hit-zones стрелок ‹/› (опционально)
  slider: {...},       // карусель из нескольких слотов (как постеры в гл.1)
  archive: {...},      // фото-карусель + кассеты (как архивы Шварца / Дашкевича)
  video: {...},        // одиночный видео-плеер
}
```

Все координаты слотов/стрелок/видео хранятся как **дроби от ширины/высоты главы** (например `848 / W`, `6201 / CH2_H`). Это позволяет рендерить главу на любой ширине экрана с сохранением пропорций.

### Координаты из Figma

Когда я брал коорды из Figma, важно было использовать **`localPosition`** ноды, а не `absoluteBoundingBox`. Frame главы стартует в Figma с произвольной X (например `x=2205`), и absoluteX надо вычитать. `localPosition` уже содержит правильные SVG-frame-relative значения.

Пример: postcard image 35 в гл.1 имеет absoluteX=127, но frame чапки начинается на `x=-102`, поэтому реальная локальная X = `127 - (-102) = 229`. В data использовать **229**, не 127.

### Кроп SVG

Figma экспортирует SVG в полную высоту фрейма, включая пустую теплую зону снизу. Я обрезаю SVG скриптом (см. `/tmp/svg-crop/crop6.js` локально или использовать паттерн ниже):

1. Растеризовать SVG в 240px шириной через `rsvg-convert`.
2. Построить «палитру пустого фона» из нижних 4% строк.
3. Идти снизу вверх и найти первую строку с цветами вне палитры — это конец контента.
4. Обновить `width`/`height`/`viewBox` атрибут самого `<svg>` элемента (без удаления контента — пиксели ниже viewBox автоматически скрываются).

Если librsvg падает на больших SVG (`Premature end of data`), парсить координаты `<rect y="..." height="...">` напрямую регэкспом — этот fallback использован для chapter 2 (он 14MB).

## Чем отличаются типы интерактива

### `slider` (глава 1)

Несколько слотов с одной поджимной картинкой каждый, циклически меняются. State: `photoIdx`. Управляется стрелками. Слот `i` показывает `pool[(i + photoIdx) % len]`.

### `archive` (главы 5, 6)

Фото-карусель + независимые кассеты с аудио.
- **`photoIdx`** — двигается **только стрелками**, переключает фото.
- **`trackIdx`** — двигается **только кликом по кассете**, переключает аудио-трек.
- Они независимы. Стрелки не влияют на музыку, кассеты не влияют на фото.
- На играющей кассете — красная заливка + эквалайзер из 3 полосок.
- Если у архива `noAudio: true`, кассеты только переключают фото и показывают видимый label.

### `video` (главы 1, 4)

Одиночный плеер. Click на постер → `<video controls autoPlay>` подменяет постер.

## Workflow для будущих правок

### Поменять текст / лейблы кассет / порядок треков

→ только `src/data/chapters.js`. Никакого build не нужно — Vite HMR подхватит.

### Добавить главу

1. Получить SVG ноды через `mcp__claude-talk-to-figma-mcp__get_svg`.
2. Сохранить в `public/assets/chapter-N-...svg`, обрезать высоту (см. «Кроп SVG»).
3. Добавить запись в `CHAPTERS` массив.
4. Добавить пункт в навбар `App.jsx`.

### Заменить слайды / фото

Положить новые файлы в `public/assets/slides/<имя>/`, обновить путь в `chapters.js` (`pool: [...]`).

### Заменить аудио

Положить mp3 в `public/assets/audio/<композитор>/`, обновить путь `audio:` в треке.

## Известные нюансы

- **`<img>`, не `<object>`** для слайдов — `<object>` не уважает `object-fit: cover`. Слайд-SVG имеют `preserveAspectRatio="xMidYMid slice"` для заполнения слота без полей.
- **viewBox у слайдов кропнут** до внутреннего content rect, обводка из Figma убрана — иначе у слайда был внутренний margin от stroke.
- **`base: './'`** в `vite.config.js` обязателен — иначе Electron в prod не найдёт ассеты по `file://`.
- **Дашкевич mp3** скачаны с `muzofond.fm` (98 треков в коллекции, выбраны 6 по фильмам). На десктопе пользователя их нет.
- **Шварц mp3** взяты из `Музыка дашкевич.zip` на десктопе пользователя (название архива было ошибочное — внутри только Шварц).
- **Главы 1, 3, 4** — не страницы конкретного композитора, а тематические разделы (город, отдельные страницы). Архивов у них нет.
